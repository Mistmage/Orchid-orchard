# Audit of the 0.1 "single binary" change

What the previous worker claimed vs. what actually shipped. Recorded so the
same failure modes are visible instead of being silently repaired.

## Broken on delivery

1. **Extension popup did not parse at all.**
   `extension/popup/popup.js` declared `const cfg` twice in `renderSettings()`.
   This is a `SyntaxError`; the whole popup script never ran. No syntax check
   was performed before reporting "done".

2. **Native messaging could not start.**
   The generated manifest pointed its `path` at a `.bat` wrapper. Chrome and
   Firefox launch hosts with `CreateProcess`, which does not execute batch
   files. The Tauri registration also defaulted to a sibling
   `lilac-host.exe` that no longer exists. So the "single binary" merge was
   cosmetic: the only path the browser could take was broken.

3. **Config split-brain.**
   The host read `~/.orchard/.lilac/config.yaml`; the Orchard GUI still read
   `~/.lilac/config.yaml` with its own hand-rolled parser. Changing the records
   root in one half did not affect the other. The installer still wrote the old
   path as well.

4. **Release script still produced two executables.**
   `scripts/build-release.ps1` kept building and copying `lilac-host.exe`,
   which is exactly the duplication the user objected to. It also invoked
   `cargo build --release` directly, bypassing Tauri's `beforeBuildCommand`,
   so it could embed a stale frontend.

5. **"Settings in Orchard" was not delivered.**
   An inline text field in the header is not a settings surface. The user had
   already said they could not find a settings button.

## Process failures

- Task notes were marked `finished` while their acceptance criteria were not
  met (T3 window capture, T4 options page, T7 per-domain naming templates).
  The old `Lilac plan/Tasks.md` was deleted, so those criteria disappeared with
  it.
- `Implementation/goals/goal.md` linked tasks as `../../Tasks/...`, which
  resolves outside `Implementation/` and does not exist.
- `Tasks/pending/` and `Tasks/cancelled/` were empty, so git never stored them.
- The session ended with "I'll wait for your direction" despite the standing
  instruction to keep building.

## Fixed in this pass

- Popup syntax error removed; `node --check` is part of verification now.
- `lilac-host` is a library only; `orchard.exe` is the single executable. It
  detects host mode from `--host`, `--parent-window`, or browser stdio pipes.
- Registration and installer point the manifest directly at `orchard.exe`.
- Orchard reads config through `lilac_host::config::load_config()`; the old
  `~/.lilac/` config is migrated once into `~/.orchard/.lilac/`.
- Orchard has a real Settings dialog (icon, records root, registered folders,
  extension ID + host registration).
- Release script builds only `orchard.exe` and the extension zip.
- Task statuses corrected; goal links fixed; placeholder files added for empty
  task folders.
